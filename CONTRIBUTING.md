# Contributing to langyo.github.io

This is a personal website and its hand-written Zola theme, `hikari-zola`. Bug
reports, focused fixes and documentation corrections are welcome; the merge bar is
deliberately high, because the repository doubles as the reference implementation of
the theme.

## What is welcome

- bug reports with a reproducible page URL, browser and viewport;
- accessibility and performance fixes (contrast, focus order, budgets, link rot);
- documentation corrections (README, AGENTS.md, theme README);
- focused improvements to the theme templates, SCSS or the native-JS modules.

## What will not be merged

- large unsolicited rewrites or a different visual language;
- new runtime dependencies, web fonts, icon packs, CSS frameworks or CDN links —
  the theme is deliberately dependency-free;
- machine-generated pull requests that were never built locally;
- design documents, changelogs or roadmap files inside the source tree. The pull
  request description *is* the design record and the merged history is the
  changelog.

## Before you open a pull request

1. Branch from `master`. The retired `dev` branch model is not used here and no
   pull request will be opened against it.
2. Run the local gate:

   ```console
   just verify                # zola build + static gate + internal link check + devtools drift
   # or piecewise:
   zola build
   python scripts/check_site.py --ci
   zola check --skip-external-links
   celestia-devtools init --check
   ```

3. For a visual change, attach screenshots at 360 px, 768 px and 1280 px, light and
   dark, and state which design tokens moved.
4. Keep the static budgets: `style.css` <= 64 KiB (gzip <= 12 KiB), theme JS
   <= 14 KiB (backdrop <= 22 KiB), one `<h1>` per page, every `<img>` with
   `width` and `height`, every published image <= 300 KiB, no CDN request
   anywhere.
5. Sign off every commit (`git commit -s`): the sign-off is a
   [Developer Certificate of Origin](https://developercertificate.org/) statement.
   There is no separate CLA to sign.

> **Base URL note.** `check_site.py` derives the site host from `base_url` in
> `config.toml`, so a scratch build made with
> `zola build --base-url http://127.0.0.1:PORT` sees every internal link as dead.
> Either gate a *baseline build* that used the default `base_url`, or point
> `--config` at a copy of `config.toml` whose `base_url` matches the scratch URL:
> `python scripts/check_site.py --config /tmp/config.local.toml`.

## Commit messages and merge model

- Message convention: a gitmoji plus a capitalised English declarative sentence,
  e.g. `✨ Add hikari-zola theme skeleton.` — enforced by the `commit-msg` hook
  installed by `celestia-devtools init` and by the shared lint workflow.
- `master` only moves through squash-merged pull requests. No direct pushes, no
  merge commits.
- Do not add a `CHANGELOG.md`; release notes are generated by the tooling.

## AI-generated contributions

This project is developed largely with AI agents, and the licence is written for
that. Disclosure is a licence obligation, not a courtesy: SySL-1.0 Section 2.3 asks
every contribution distributed as source code to state, at the file or commit level,
whether it was AI-generated, human-written, or a combination, and which models were
used. State it in the commit message, and in the file header when the file is new.

## Security

Do **not** open public issues for security vulnerabilities. Report them privately
through GitHub Security Advisories — see [`SECURITY.md`](SECURITY.md).

## Code of conduct
